# Provenance and Trust State Specification

## 1. Core Principle

In FLN (Foundational Literacy and Numeracy) education in tribal mother tongues, **linguistic trust is paramount**. A machine hallucination or distorted pronunciation delivered as "authoritative native speech" misleads young learners and damages teacher confidence.

Therefore, SIH26042 enforces a **strict, multi-dimensional provenance model**. 

We explicitly distinguish between:
1. **Translation Linguistic Verification**: Did a qualified native educator review the text and semantics?
2. **Audio Speaker Authenticity**: Was the WAV recorded by a native speaker in a studio/controlled environment, or generated by an acoustic model?
3. **Engine Confidence**: Mathematical confidence from an ASR or MT model.
4. **Phrase-Match Exactness**: Levenshtein / Token similarity score against curated classroom phrases.

---

## 2. Provenance State Taxonomy

| Provenance State | Meaning | Classroom Suitability | Audio Source |
|---|---|---|---|
| **`VERIFIED`** | Source Hindi, Ol Chiki script, meaning, intent, audio recording, and reviewer identity have all been validated. | Full Unrestricted Classroom Use | Native Speaker Studio WAV (16 kHz, 16-bit PCM) |
| **`PENDING_VALIDATION`** | Syntactically correct or draft phrase awaiting formal native-speaker linguistic sign-off or studio audio. | Teacher Review Only (Prompts verification) | Draft or Missing Audio |
| **`MACHINE_GENERATED`** | Synthesized dynamically via on-device Quantized Neural MT (IndicTrans2) or experimental TTS. | Warning Displayed (Teacher must verify before repeating to children) | Visual Text Only or Synthesizer (Explicitly flagged) |
| **`TEACHER_CORRECTED`** | Modified by an in-service classroom teacher on-device; stored in local queue awaiting backend sync. | Local Classroom Override Only | Local Recording or Muted Text |
| **`UNAVAILABLE`** | Requested feature (e.g. offline neural TTS) cannot safely execute within target hardware budget. | Safe degradation to text/prerecorded audio | None (Silent / Explicit Message) |

---

## 3. Strict Promotion Policy (No Auto-Promotion)

A phrase item is promoted to `VERIFIED` **ONLY IF ALL FIVE** conditions are met:
1. `source_hindi_verified == true`
2. `santali_text_verified == true` (Ol Chiki glyphs validated against unicode standard)
3. `meaning_intent_approved == true`
4. `native_audio_approved == true` (Acoustics pass clipping, SNR, DC offset, and native phonology audit)
5. `reviewer_id` is a non-null, registered reviewer record with a valid ISO-8601 validation timestamp.

**If any single element is missing**, the runtime forces status:
```
PENDING_VALIDATION
```

Automatic promotion by scripts, MT outputs, or developer intuition is strictly prohibited.
